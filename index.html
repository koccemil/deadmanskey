🛡️ This Is My Risk
Güvenlik Analizi
Sözleşme kodu Remix Static Analyzer ile taranmış ve manuel olarak incelenmiştir. Aşağıda tüm bulgular ve değerlendirmeleri yer almaktadır.
✓ Gerçek Risk Yok1. Reentrancy (Tekrar Giriş Saldırısı)
releaseAll() · emergencyWithdrawETH() · withdrawFees()
Araç, ETH transferi yapan fonksiyonlarda Checks-Effects-Interactions ihlali olabileceğini bildirdi. Ancak releaseAll()'da fundsReleased = true ETH transferinden önce set edilmektedir — tekrar çağrı gelirse notReleased modifier reddeder. Ayrıca fonksiyon yalnızca onlyBeneficiary ile kilitlidir; harici bir saldırgan erişemez. Remix bu uyarıyı modifier'ları analiz etmeden otomatik verir.
✓ Gerçek Risk Yok2. block.timestamp Manipülasyonu
timeExpired modifier · ping() · timeRemaining() · canRelease()
Base ağı Proof-of-Stake kullanmaktadır; validator timestamp sapması ~2 saniye ile sınırlıdır. Sözleşmedeki minimum timeout 7 gün (604.800 saniye), maksimum 365 gündür. 2 saniyelik sapma bu süreler için tamamen anlamsızdır.
✓ Gerçek Risk Yok3. Low Level .call Kullanımı
releaseAll() · emergencyWithdrawETH() · withdrawFees()
ETH transferi için .call{value: x}("") günümüzde Solidity'nin önerdiği standart yöntemdir. Eski transfer() ve send() EIP-1884 sonrasında gas sorunları nedeniyle terk edilmiştir. Tüm .call çağrılarının dönüş değeri kontrol edilmekte, başarısız olursa işlem geri alınmaktadır.
▲ Düşük — Kontrol Altında4. Dinamik Dizi Döngüsü (Gas Limiti)
releaseAll() · addToken() · removeToken()
Token listesi büyüdükçe releaseAll() gas tüketimi artar. Ancak token ekleme yetkisi yalnızca sözleşme sahibindedir; sahip kendi aleyhine bu riski yaratmaz. Varsayılan yalnızca 3 token (USDC, USDT, WBTC) mevcuttur. V3 sözleşmesinde MAX_TOKENS = 20 hard limit eklenmiştir.
✓ Gerçek Risk Yok5. Tek Dosyada Birden Fazla Contract
ReentrancyGuard · DeadMansKey · DeadMansKeyFactory
Solidity tek dosyada birden fazla contract tanımlanmasına izin verir. Bu yaygın bir pratiktir ve güvenlik açığı değil kod organizasyonu tercihidir.
✓ Gerçek Risk Yok6. Custom Error Yerine require
Tüm require ifadeleri
Custom Errors gas açısından daha verimlidir ancak require güvenlik açısından tamamen geçerlidir. Bu bir optimizasyon önerisidir, güvenlik açığı değildir.
✓ Gerçek Risk Yok7. Hata Mesajı Uzunluğu
Solhint'in 32 karakter sınırı stilistik bir kuraldır; Solidity'nin zorunlu kısıtlaması değildir. Uzun mesajlar yalnızca hafif gas artışına yol açar.
✓ Gerçek Risk Yok8. Constructor Visibility
Solidity 0.7.0+ sürümlerinde constructor visibility implicit olarak public'tir. Sözleşme ^0.8.20 kullanmaktadır; bu eski versiyonlara yönelik bir uyarıdır.
✓ Gerçek Risk Yok9. Benzer Değişken İsimleri
MIN_TIMEOUT ve MAX_TIMEOUT kasıtlı olarak benzer isimlendirilmiş constant değişkenlerdir. Her biri doğru bağlamda kullanılmaktadır; yazım hatası değildir.
✓ Gerçek Risk Yok10. IERC20 Interface Return Değeri
Interface tanımları gövde içermez; return değeri implement eden kontrat tarafından sağlanır. Bu Solidity'nin temel sözdizim kuralıdır.
📊 Genel Değerlendirme
Tespit edilen 10 bulgunun 9'u gerçek bir saldırı vektörü içermemektedir. 1 bulgu (gas limiti) düşük seviyeli ve kontrol altındadır. Sözleşme üretim ortamında kullanım için yeterli güvenlik seviyesine sahiptir.
✓ No Real Risk1. Reentrancy
releaseAll() · emergencyWithdrawETH() · withdrawFees()
The tool flagged potential Checks-Effects-Interactions violations in ETH-transferring functions. However, in releaseAll(), fundsReleased = true is set BEFORE the ETH transfer — any reentrant call is rejected by the notReleased modifier. The function is also gated by onlyBeneficiary; no external attacker can access it. Remix generates this warning automatically without analyzing modifiers.
✓ No Real Risk2. block.timestamp Manipulation
timeExpired modifier · ping() · timeRemaining() · canRelease()
Base uses Proof-of-Stake consensus; validator timestamp deviation is limited to ~2 seconds. The contract's minimum timeout is 7 days (604,800 seconds), maximum 365 days. A 2-second deviation is completely irrelevant over these durations.
✓ No Real Risk3. Low Level .call Usage
releaseAll() · emergencyWithdrawETH() · withdrawFees()
.call{value: x}("") is the current Solidity-recommended standard for ETH transfers. The older transfer() and send() were deprecated after EIP-1884 due to gas issues. All .call return values are checked — failed calls revert the transaction.
▲ Low — Controlled4. For Loop Over Dynamic Array
releaseAll() · addToken() · removeToken()
Gas usage in releaseAll() grows with token list size. However, only the contract owner can add tokens — an owner would not deliberately create this risk against themselves. Only 3 tokens exist by default (USDC, USDT, WBTC). V3 adds MAX_TOKENS = 20 as a hard limit.
✓ No Real Risk5. Multiple Contracts Per File
ReentrancyGuard · DeadMansKey · DeadMansKeyFactory
Solidity allows multiple contracts in a single file. This is common practice and a code organization preference, not a security vulnerability.
✓ No Real Risk6. require Instead of Custom Errors
All require statements
Custom Errors are more gas-efficient but require is completely valid from a security standpoint. This is an optimization suggestion, not a vulnerability.
✓ No Real Risk7. Error Message Length
Solhint's 32-character limit is a stylistic rule, not a Solidity requirement. Longer messages only add minor gas overhead.
✓ No Real Risk8. Constructor Visibility
Since Solidity 0.7.0, constructor visibility is implicitly public. This contract uses ^0.8.20; the warning targets legacy versions.
✓ No Real Risk9. Similar Variable Names
MIN_TIMEOUT and MAX_TIMEOUT are intentionally named constants, each used correctly in its context. Not a typo or logic error.
✓ No Real Risk10. IERC20 Interface Return Value
Interface definitions have no body by design; return values are provided by the implementing contract. This is fundamental Solidity syntax.
📊 Overall Assessment
9 of 10 findings contain no real attack vector. 1 finding (gas limit) is low-severity and controlled. The contract meets sufficient security standards for production use.
Mirasçı Rehberi
Sana bir DMK sözleşmesi bırakıldıysa aşağıdaki adımları takip et.
01
Sözleşme adresini öğren
Sözleşmeyi kuran kişi sana bir adres bırakmış olmalı. Bu adres "0x..." ile başlar. Güvenli bir yerde sakla.
02
Sürenin dolmasını bekle
Sahip ping atmayı bıraktıktan sonra belirlenen süre (genellikle 30 gün) dolmalıdır. Basescan'da "timeRemaining" ile kontrol edebilirsin.
03
Cüzdanını bağla
Sözleşmede kayıtlı mirasçı adresi senin cüzdanın olmalı. MetaMask veya uyumlu bir cüzdan ile bu siteye bağlan.
04
"Mevcut sözleşmemi yükle" seç
Ana ekrandan "Mevcut sözleşmemi yükle"ye tıkla, sözleşme adresini gir ve yükle.
05
Release All — fonları al
Panel ekranında "mirasçı çekimi" butonuna bas. ETH ve tüm tokenlar anında senin cüzdanına transfer olur. Bu işlem geri alınamaz.
⚠ Dikkat
Süre dolmadan "Release All" çağıramazsın — sözleşme reddeder. Gas ücreti için cüzdanında küçük miktarda ETH bulundur.
